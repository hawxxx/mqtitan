# MQTTitan platform implementation plan

**Goal:** Deliver a runnable MQTT platform whose CLI and UI operate the same persisted tests, with distributed execution and CI verdicts.

**Architecture:** Go owns test lifetime independently of HTTP requests. SQLite stores redacted scenario metadata and compact metric buckets. Workers execute immutable client partitions and report cumulative snapshots. React consumes one-second SSE samples through bounded history.

**Spec:** docs/architecture/overview.md and the user's full product specification.

## Constraints

- User authorizes autonomous implementation without approval pauses.
- MQTT 3.1.1 and MQTT 5; bounded queues; no raw message persistence.
- Never log or store plaintext broker passwords; require token for remote control.
- Report measured support honestly; million-client capacity requires dedicated qualification.

## Review focus

- Cancellation during connect and publish must join work and close sockets.
- Stage transitions must preserve publishers and implement downward targets.
- Browser disconnect must leave tests running; telemetry slow consumers cannot block load.
- Thresholds must reject unknown expressions and fail CI when measurements violate them.
- Restart must mark unfinished tests interrupted and preserve historical results.

## Execution

- [x] Engine agent: failing stage/lifecycle tests, real broker tests, MQTT5, TLS, scenarios, bounded metrics.
- [x] Controller: failing persistence/restart/API tests; SQLite repository; background run manager; REST and SSE.
- [x] CLI: thresholds, live local controller, exports, remote commands, doctor.
- [x] UI agent: API-backed wizard, live uPlot, scenarios/results/workers, responsive themes and tests.
- [x] Operations agent: Docker/Compose, Helm, CI and operational docs.
- [x] Distributed worker registration, partitioning, health and cumulative telemetry.
- [x] Optional EMQX polling and comparative reports.
- [ ] Integration: race tests, static analysis, MQTT compatibility, browser workflow, image/chart checks.

The existing single-client goroutine/library transport is a correctness baseline. Capacity certification requires memory/client and telemetry benchmarks on specified hardware; no unmeasured performance promise is a release guarantee.
